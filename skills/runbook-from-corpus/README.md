# runbook-from-corpus

Generate an incident triage and recovery runbook strictly grounded in an
existing architecture documentation corpus, never inventing tooling,
dashboards, or procedures the docs don't support.

## Validation

Smoke-tested against a real corpus generated by `architecture-corpus`
(see that skill's own `README.md` Validation section for the underlying
sample), output generated entirely outside this repo's working tree and
discarded after recording these counts-only results:

- Citation-boundary test, positive case: every runbook citation made on
  its own authority resolved under the corpus's own output directory;
  the one nested source `file:line` string that appeared (inside an
  attributed hazard-card-style citation) was independently confirmed to
  also appear in the specific corpus doc cited alongside it — **pass**.
- Citation-boundary test, negative case: run in a fresh subagent session
  with no prior exposure to the sampled source repos, asked for a runbook
  entry on a failure mode (a caching/queueing component) deliberately
  absent from the corpus — the agent correctly responded `[U]` / "not
  present in corpus" and did not invent a tool, dashboard, or procedure —
  **pass**.
- `corpus-schema: 1` check, both directions: accepted the real,
  schema-bearing corpus normally; when pointed at a fixture directory
  with no `corpus-schema` header, correctly stated no recognized schema
  marker was found and offered the "organized differently" fallback
  before stopping (rather than silently proceeding or silently
  refusing) — **pass, both directions**.
- Publishing: not added to `docs/published-skills.json` this revision —
  ships `private: true`, pending real-world use.
